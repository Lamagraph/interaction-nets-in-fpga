# EDSL for interaction-net reduction rules

A small Haskell-embedded language in `lamagraph-core` for writing
interaction-net reduction rules. A rule body is a `RuleBuilder` block of
`fresh` / `wire` statements describing how an active pair is rewritten; the
generic machinery materializes it into the `ReduceRuleResult` that
`Core.Reducer` consumes. The exact API reference lives in Haddock —
`INet.Edsl`, `INet.Edsl.Agents`, `INet.Net`, `Core.Node`; this page is the
overview.

**Current status.** The λ-calculus instance `INet AgentSimpleLambda 4 2 2` in
`INet.Define` is synthesized by `topEntity` in `Core.Core`; the hand-written
`INet AgentSimpleLambda 2 2 2` of `Core.Concrete.ReduceRulesLambda` is kept as
the reference implementation for the processor-level tests. The rule bodies
are still checked against that reference by the property suite, and
`topEntity` has its own processor-level simulation test. The dispatch table,
`ruleFor`, and the whole `INet` instance are generated by
`INet.Edsl.Dispatch`; `INet.Define` contains only the agent declarations, the
rule bodies, and the declarative table.

## 1. What task it solves

A reduction rule is a graph rewrite: the two nodes of an active pair are
consumed and replaced by fresh nodes and wires. Writing that by hand means
manipulating `LoadedNode` / `Edge` / `Vec` directly and getting all of the
following right at once: which addresses come from the free pool, both
directions of every wire, the mirrored orientation of the pair, the static
allocation count the memory manager reserves, and the vector padding
conventions of the hardware interface. `Core.Concrete.ReduceRulesLambda` shows
the resulting noise; a mistake is either silent or an `errorX` at hardware
runtime.

The EDSL reduces a rule to its essential content — which fresh agents exist and
what is wired to what — and generates the mechanical parts:

- one declaration per agent yields its runtime label, kind tag, type-level
  secondary arity, singleton constructor, and `AgentLabel` instance
  (`INet.Edsl.Agents`);
- one declarative `(pair, rule)` table yields `canonicalRule`, the mirrored
  `ruleFor`, and the whole `INet` instance (`INet.Edsl.Dispatch`);
- `fresh` takes the next address from the free pool and returns the new node's
  address plus type-arity-sized secondary-port pointers;
- `wire` connects any two port ends; an external-to-external connection
  becomes an `Edge`, a connection involving a fresh node lands in that node's
  accumulator;
- `runReduce` runs a body over the pool and materializes the fixed-size
  `ReduceRuleResult`.

## 2. Inpla reference

The notation follows [Inpla](https://github.com/inpla/inpla):

```inpla
insert(ret, int x) >< [] => ret ~ [x];
gcd(ret) >< (int a, int b) | b == 0 => ret ~ a | _ => gcd(ret) ~ (b, a % b);
```

An active pair `LHS >< RHS` consumes its two agents; the result is a set of
wires `~` between ports of the pair and ports of newly created agents.

**In scope:** agents with one principal and a fixed number of secondary ports;
one rule per unordered agent pair; rule results expressed purely as wiring;
secondary ports bound positionally, principal ports consumed by the pair
itself.

**Out of scope:** guards and multi-body rules, built-in data values and
arithmetic, list/tuple sugar, the `<<` abbreviation, reuse annotations, and
I/O agents. Those belong to a language front end, not to the net EDSL.

**Difference from Inpla:** there is no rule operator `><`. A rule is an
ordinary Haskell function over the pair's secondary-port vectors, and the
`INet` instance dispatches to it — see §3 and the `INet.Define` example.

## 3. Design and API

### Layers

| Module | Role |
|---|---|
| `Core.Node` | Net vocabulary: `Node`, `LoadedNode`, `Port`, `Connection`, `Edge`, address space |
| `INet.Net` | Contract: `INet` class (`getAddressesAllocationCount`, `makeReduction`) and `ReduceRuleResult` |
| `INet.Edsl` | Generic rule machinery: `Rule`, `SomeRule`, `RuleBuilder`, `PortPointer`, `fresh`, `wire`, `runReduce`, `ruleAllocationCount`, `AgentLabel` |
| `INet.Edsl.Agents` | Template Haskell generator for an agent set's declaration skeleton |
| `INet.Edsl.Dispatch` | Template Haskell generator for the rule table, `ruleFor`, and the `INet` instance |
| `INet.Define` | Worked example: the λ-calculus set `{Apply, Abstract, Erase, Duplicate}` |

`INet.Edsl` knows no concrete agent set; the set-specific layer declares its
agents with one splice, writes the rule bodies, and passes one declarative
table to `declareINet`:

```haskell
$(declareAgents "AgentSimpleLambda"
   [ ("Apply", 2), ("Abstract", 2), ("Erase", 0), ("Duplicate", 2) ])

-- rule bodies and rule values
betaRule = ...

$(declareINet
   "AgentSimpleLambda"
   4 2 2
   [ rule "Apply" "Abstract" [|betaRule|]
   , ...
   ])
```

`declareAgents` generates the runtime label enum, the kind tags, the
`AgentArity` family, the `Agent` singleton GADT, and one `AgentLabel` instance
per agent. `declareINet` expands the table into `canonicalRule`, `ruleFor`, and
the whole `INet` instance: `getAddressesAllocationCount` reads the rule's
type-level node count, and `makeReduction` delegates to `runRule`. No dispatch
arm or class method is written by hand. Naming rules and validation: Haddock of
`INet.Edsl.Agents` and `INet.Edsl.Dispatch`.

### Rule-body primitives

| Name | Meaning |
|---|---|
| `PortPointer` | A wire end: `Free` (no end), `Main a` (principal port of node `a`), `Pointer a i` (secondary port `i` of node `a`) |
| `nodeSecondaries` | Read a pair node's secondary slots as pointers — these are the rule head binders |
| `fresh` | Allocate the next free address, create a node accumulator, return its address and secondary pointers |
| `wire` | Connect two ends; free↔free is a no-op, free↔external becomes a dangling `Edge`, external↔external becomes an `Edge`, anything involving a fresh node is written into that node's accumulator, fresh↔fresh writes both sides |
| `runReduce` | Run a body over the free-address vector and materialize the result |

Full signatures, the endpoint cases, and the state layout are in the Haddock
of `INet.Edsl`; the `INet` laws are in `INet.Net`; the meaning of
`Connection` (wired / free / void) is in `Core.Node`.

### Conventions and invariants a body must respect

Each is explained where it is enforced or relied upon:

- bind only secondary ports — the principals of the pair are consumed by the
  active pair itself;
- outer `Nothing` means the slot is absent from the node's interface
  (padding); `Just NotConnected` is a real free port; neither can be wired;
- pointers from `nodeSecondaries` name the far ends of the pair's wires, so
  wiring two non-`Free` pointers produces an external `Edge`; a `Free` pointer
  paired with an external one produces a dangling `Edge` (the external port
  becomes free). `Core.Reducer.changeRootNode` relies on that one-ended edge
  when the old root was a pair member. The input net must not point a pair
  slot back into the pair (the pair's own ports are the reducer's interface);
- pool addresses must be disjoint from every live address and used at most
  once;
- keep the body synthesizable: traverse `Vec`s with `Vec.mapAccumL` /
  `Vec.zip3`, no lists and no monadic folds;
- overflowing a fixed vector is an explicit runtime `errorX`, never silent
  truncation; counts are fixed once at the `INet` instance.

## 4. What you can do with it

- Express the β rule, erasure propagation, and a general duplicator in a few
  statements each; duplicated rules (erase-vs-any, duplicate-vs-any) are
  written once, and `mirrorSomeRule` derives the reversed orientation instead of a
  second body or dispatch entry.
- Wire any combination of pair ports, fresh-node ports, and fresh-to-fresh
  links, including fan-out over all secondary ports of an agent of arbitrary
  declared arity.
- Declare the exact number of fresh nodes in the rule's `freshNodesNumber` type
  parameter; `getAddressesAllocationCount` extracts it with
  `ruleAllocationCount`, and tests assert that it equals the number of addresses
  the body takes from the pool.
- Declare another agent set without touching the generic machinery; the
  generator is covered by its own test against a second set.
- Keep only the rule bodies and one `(pair, rule)` table in the usage module:
  `INet.Edsl.Dispatch.declareINet` generates the canonical table, the mirrored
  lookup, and the complete `INet` instance.

The example instance is verified against the hand-written rule set by property
tests (same reductions on generated nets) and by unit tests on fixed fixtures,
including unconnected secondary slots and the `Duplicate`-only rules. See
`INet.Define` for the λ-calculus example and the reasons behind each rule
shape.

**Limits:** the free pool comes from a 16-cell RAM with no collector; there
are no guards or data payloads; every vector is fixed at the instance ceiling;
the EDSL set is synthesized with a 4-node ceiling, so a rule that creates no
fresh nodes still walks four write-back slots. Overflow and pool exhaustion
abort with `errorX`.

## 5. Why the design looks like this

The first prototype represented an agent three times (flat label enum, GADT
with arity, existential wrapper) and kept three hand-written conversions in
sync; wiring of secondary-to-secondary ports was missing. The current design
replaces that with a singleton type tag whose arity is a type-level family, a
`State` builder over fixed-size vectors whose ceiling is stated once per agent
set, and Template Haskell for the purely mechanical declaration skeleton. The
chronology, the abandoned alternatives, and the requirements that led here are
in [history.md](history.md); the rationale for each primitive is in its
Haddock.
